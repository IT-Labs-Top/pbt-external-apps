# Демоприложение «Фотооткрытка»

Это законченный пример внешнего приложения на обычном JavaScript. Он получает настройки услуги, принимает оплату через SDK, снимает фото, собирает открытку в Canvas, печатает её и показывает QR для скачивания.

## Запуск

Нужен Node.js 24+. Скачайте репозиторий и выполните из его корня:

```sh
node sandbox/start.mjs --app=demos/postcard
```

Альтернатива — `npm run demo` (`npm.cmd run demo` при ограничениях PowerShell). Устанавливать зависимости или собирать интерфейс не требуется. Встроенная страница проверки отдельных методов SDK по-прежнему запускается командой `node sandbox/start.mjs`.

Откройте адрес из терминала и нажмите «Применить настройки и начать сессию». В области приложения появится «Фотооткрытка».

## Пройти сценарий

1. Нажмите «Начать» в приложении. Во вкладке песочницы «Оплата» одобрите карту или внесите наличные. Частичную наличную оплату можно продлить кнопкой «Добавить время» в приложении.
2. После оплаты появится камера. Нажмите «Сделать снимок» и дождитесь отсчёта. Перед оформлением кадр можно переснять.
3. Выберите рамку, оттенок и подпись. Приложение использует каталоги SDK; неподходящие для одной портретной открытки рамки не предлагаются.
4. Подтвердите оформление. При выборе нескольких открыток приложение отдельно запросит доплату за дополнительные листы по `sheetPrice`.
5. Дождитесь печати и подготовки ссылки. Сохраните файл через QR, затем завершите сессию.

Для `fulfillment=digital` печать и доплата не выполняются. Нулевая цена пропускает начальную оплату. Все операции в песочнице имитируются.

QR локальной песочницы открывает галерею **на том же компьютере**. Её можно открыть из вкладки «Результаты». Скачивание на телефон требует работающего сервера панели администратора; этот сценарий проверяется на фотобудке.

## Исходники и готовый пакет

Исходники находятся в папке `demos/postcard` публичного репозитория. Это самостоятельная папка статического приложения: `index.html`, `style.css`, `service.json`, `src/`, `assets/`, `vendor/sdk.js`. Скопируйте её в свой проект и запускайте через `--app=путь`.

| Файл | Что изучить |
|---|---|
| `src/app.js` | Основной сценарий, вызовы SDK, ошибки и жизненный цикл. |
| `src/operations.js` | Одно действие — один ID и неизменные аргументы до установления результата. |
| `src/postcard.js` | JPEG 1200×1800 с настоящим эффектом, подписью и рамкой. |
| `src/weather.js` | Необязательный внешний запрос с таймаутом и продолжением основного сценария при ошибке. |
| `package.mjs` | Повторяемая сборка ZIP из тех же исходников без npm-зависимостей. |

[Скачать готовый ZIP 1.0.0](downloads/photo-postcard-1.0.0.zip) · [SHA-256](downloads/photo-postcard-1.0.0.zip.sha256).

Изменив приложение, увеличьте версию в `service.json` и выполните:

```sh
node demos/postcard/package.mjs
```

Пакет появится в `demos/postcard/dist`. README и инструмент упаковки в ZIP не входят. Не меняйте опубликованные файлы под прежней версией. Для своего приложения измените ID и имя в манифесте. [Правила пакета и передачи администратору](PACKAGE.md).

## Публичные настройки

Пример `config`:

```json
{
  "city": "Самара",
  "weather": { "enabled": false, "latitude": 53.1959, "longitude": 50.1008 }
}
```

Погода отключена по умолчанию. При `weather.enabled=true` приложение выполняет запрос к объявленному origin `https://api.open-meteo.com`. Геолокация посетителя не используется. Ошибка, отсутствие интернета или таймаут погоды не блокируют оплату и создание открытки.

[Open-Meteo](https://open-meteo.com/) предоставляет данные с атрибуцией CC BY 4.0; источник указан в интерфейсе и на открытке с погодой. Бесплатный endpoint — для некоммерческого использования. Для коммерческого применения нужны подходящие условия поставщика и соответствующие изменения кода/манифеста; секреты в клиентском коде хранить нельзя.

## Проверить ошибки

- Потеря ответа или задержка: приложение продолжает прежний запрос и не создаёт новую оплату, снимок или печать автоматически.
- Отказ карты без внесённых денег: можно явно начать новую попытку. Частично внесённые деньги требуют сверки прежней оплаты.
- Частичная печать: показывается число подтверждённых листов; автоматического повторного задания нет.
- Сервер панели администратора недоступен после печати: повторяется подготовка ссылки, готовые листы не печатаются повторно.
- Пауза: ввод, отсчёт и предпросмотр останавливаются; уже принятые операции учитываются после продолжения. Остановка освобождает ресурсы.
- Перезагрузка страницы в начатой сессии: новый сценарий блокируется до сверки прежних операций. Пример не восстанавливает Canvas после перезагрузки и не начинает новую оплату поверх старой.
- «Помощь и возврат»: запрос проверки возврата передаётся программе фотобудки, без объявления банковской операции успешной по одному приёму запроса.

События `postcard.*` записывают этапы, попытки и ошибки с ID операций. Подпись и байты фото в события не передаются. [Как скачать диагностику](SUPPORT.md).

Песочница проверяет логику и контракт SDK. Драйверы, реальная ориентация камеры, фактическая печать, оплата и банковские возвраты требуют отдельного прогона на тестовой фотобудке.
