Песочница#

Песочница запускает ваше приложение рядом с панелью разработчика и предоставляет локальный API с имитацией оборудования. Приложение вызывает настоящий SDK: команды, ожидание результата, ошибки и повторы проходят по HTTP. Реальные деньги, устройства и сервер панели администратора не используются.

Запуск одной командой#

Нужен Node.js 24+. Скачайте или клонируйте репозиторий, откройте терминал в его корневой папке и выполните:

node sandbox/start.mjs

Команда выводит локальный адрес, обычно http://127.0.0.1:4174. Откройте его в браузере. Установка npm-пакетов не нужна; Python и Electron также не требуются. Альтернативная команда — npm start (в Windows при запрете PowerShell-сценариев используйте npm.cmd start).

По умолчанию загружается встроенная страница проверки SDK. Нажмите «Применить настройки и начать сессию», затем:

  1. В приложении начните оплату; в панели «Оплата» одобрите карту или внесите наличные.
  2. Сделайте снимок. По желанию загрузите JPEG, чтобы проверить обработанный результат.
  3. Напечатайте выбранное количество листов.
  4. Подготовьте ссылку и QR; откройте локальную галерею из панели «Результаты».
  5. Завершите услугу. Для следующей проверки начните новую сессию.

Остановка — Ctrl+C в терминале. Песочница хранит данные в памяти: после остановки они исчезают. Сохраните журнал и нужные JPEG до завершения процесса.

Своё приложение#

Передайте папку готовой статической сборки с service.json в корне:

node sandbox/start.mjs --app=C:/projects/my-app/dist

Или:

npm start -- --app=../my-app/dist

Сборку React/Vue сначала подготовьте обычной командой своего проекта. Используйте относительные ссылки на ресурсы: приложение открывается по вложенному адресу, как на фотобудке. Песочница не запускает npm-скрипты переданной папки и не принимает URL dev-server вместо готовых файлов.

Ваш сайт использует ExternalClient и публичный контракт SDK. Заменять методы SDK или добавлять вызовы панели разработчика в приложение не требуется. Песочница предоставляет window.pbtService для start/pause/resume/stop и диалога выхода. Обрабатывайте паузу и остановку так же, как на фотобудке.

После изменения статических файлов начните новую сессию или перезапустите песочницу. После изменения service.json нужно перезапустить процесс: разрешения и сетевые адреса читаются при его запуске. ZIP-проверка и установка на реальную фотобудку выполняются отдельно.

Настройки#

Настройка Поведение
Цена услуги и дополнительного листа Возвращаются в рублях через context(). Цена листа не списывается автоматически.
Основной результат print проверяет наличие бумаги до запуска; digital позволяет проверить скачивание файлов без печати.
Разрешения Можно выбрать только объявленные в service.json. Недоступный capability нельзя выдать через панель.
Камеры Главная, верхняя и боковая; включение, отключение и ориентация тестового изображения.
Рамки и эффекты Выберите элементы тестовых каталогов, которые увидит приложение.
Публичный config JSON-объект для context().config; без config:read приложение получает пустой объект.
Бумага Начальный запас для новой сессии. Во вкладке «Оплата» запас можно менять во время печати.
Ожидание оплаты Время до таймаута, в том числе после внесения части наличных; extendCashWait продлевает текущую оплату.
Бездействие Предупреждение и выход до/после оплаты. Ожидание оборудования не считается уходом посетителя.

Изменение настроек применяется кнопкой начала новой сессии; уже начатая операция не меняется из-за редактирования поля. Настройки можно сохранить в JSON и загрузить в панели либо передать при запуске:

node sandbox/start.mjs --config=./sandbox-settings.json --port=4274

Занятый порт не освобождается автоматически: выберите другой через --port. Сервер слушает только адрес loopback. Для каждой сессии создаётся отдельный origin вида http://<runId>.localhost:<port>. Браузер должен поддерживать локальные адреса .localhost; полный сценарий проверен в Chromium. Настройки сети операционной системы менять не нужно.

Сценарии ошибок#

Сценарий Что проверить
Отказ карты Ошибка оплаты видна приложению; прежний успешный платёж не подтверждает новую попытку.
Частичное внесение наличных amountPaid растёт, оплата остаётся pending до полной суммы; «Ещё время» вызывает extendCashWait.
Задержка команды SDK может закончить ожидание раньше оборудования. Продолжите с прежним requestId.
Потерять следующий ответ Команда принимается и выполняется, но HTTP-ответ теряется. Повтор ID не должен создавать вторую операцию.
Нет ответа локального API Чтение и команды SDK получают транспортную ошибку; восстановите соединение и проверьте исход той же операции.
Сервер панели администратора недоступен share/QR не готовы; локальная съёмка и печать сохраняют работоспособность.
Ошибка камеры Снимок не создаётся; другие фотографии сохраняются.
Нет бумаги или ошибка после N листов copiesDone отражает подтверждённые листы. Частичная/неясная выдача не считается успехом.
Отказ возврата Запрос принимается отдельно от результата. Итог имитации появляется в панели оплат.

Переключатели ошибок действуют сразу. Потеря ответа — одноразовый сценарий. Задержки HTTP, выполнения команды и одного листа настраиваются отдельно. Значение −1 у ошибки после N листов отключает этот сценарий.

Встроенная проверочная страница сохраняет ID и исходные аргументы после неопределённого результата. Для payment и print при известном operationId/jobId она продолжает ожидание соответствующей операции. На новой сессии идентификаторы, фотографии и суммы не наследуются.

Результаты и журнал#

Во вкладке «Результаты» доступны снимки, загруженные JPEG, подтверждённые листы, принятые и возвращённые суммы, этапы приложения, задания печати и состояние API. Во вкладке «События» отображаются принятые команды, повторы, оплаты, печать и диагностика SDK. Кнопка «Сохранить журнал» скачивает JSON; содержимое JPEG в него не включается.

QR действительно кодирует адрес локальной галереи. Галерею можно открыть и скачать JPEG на том же компьютере. QR с адресом 127.0.0.1 не предназначен для скачивания на телефоне: для проверки этого сценария нужен сервер панели администратора. Галерея остаётся доступна после закрытия приложения, пока работает песочница, не удалена история этой сессии и не истёк часовой срок ссылки.

Хранятся до 20 последних сессий. При заполнении лимита файлов/объёма очистите предыдущие сессии. Данные не отправляются во внешние сервисы самой песочницей; внешние запросы вашего приложения остаются обычными браузерными запросами к объявленным в манифесте адресам.

Выход и режим ожидания#

Кнопки панели «Пауза» и «Продолжить» отправляют события жизненного цикла. «Выход» и requestExit() показывают подтверждение поверх приложения; добровольный exit() закрывает запуск без второго диалога. Предупреждение о бездействии можно убрать продолжением или resetIdleTimer(). На stop приложение должно вызвать dispose и остановить собственные таймеры.

Границы проверки#

Это имитация контракта, а не программа управления настоящим оборудованием. Браузерный iframe и CSP помогают воспроизводить поведение приложения, но не заменяют проверку изоляции Electron. Соблюдение CORS, доступность внешних API, ориентация и качество реальной камеры, резка бумаги, тайминги драйверов, банковские возвраты и фискализация проверяются на тестовой фотобудке.

В симуляторе автоматический возврат по карте возможен при отсутствии результата. Наличные, частичная печать, уже подготовленные файлы и неопределённая выдача помечаются для ручной сверки. Это упрощённая имитация правил, не подтверждение банковской операции и не замена финансовой политике реальной программы фотобудки.
